# 当前工作与可复用成果（通俗版）

更新时间：2026-07-23

## 一、现在正在做什么

当前工作不是继续为已经终止的题目寻找结果，而是在建立一份完整的**项目数据Atlas**。

数据Atlas可以理解为对全部研究材料进行一次系统盘点：

- 有哪些数据；
- 每类数据的观察单位是什么；
- 覆盖哪些年份；
- 企业标识能否连接；
- 字段是否有明确含义；
- 哪些变量可以正式使用；
- 哪些变量只能探索；
- 哪些路线会因为数据缺口而失败；
- 下一步最值得进入人工语义阅读和正式研究的方向是什么。

截至2026年7月23日，已经完成：

- 约49.434GB唯一机器可读内容的全量清点；
- FactSet/Revere关系数据5,245,666行全扫；
- GSDB制裁数据结构审计；
- 68,470份MD&A TXT全文机器索引；
- 170个结构化字段完整画像；
- 68,470份TXT编码审计和章节切分；
- FactSet工作副本、证券映射、关系主键、`end=4000`和coverage终局审计；
- 七类全文表示连续完成76/92批。

当前尚未完成：

- 第77—92批全文表示；
- 多方法主题模型；
- 语义残余队列；
- finalizer；
- 最终机器深度Atlas包。

## 二、编程和研究判断怎样分工

本项目中，脚本主要负责重复、批量和可核验的工作，例如：

- 扫描文件；
- 统计字段；
- 检查编码；
- 切分文本章节；
- 统一企业代码；
- 生成文本矩阵；
- 记录批次和检查点；
- 输出异常清单。

研究者负责：

- 定义研究问题；
- 决定哪些字段需要核验；
- 制定脚本规则和验收标准；
- 判断异常是否具有研究含义；
- 审核脚本输出；
- 决定路线继续、修正或终止；
- 对结果作经济和管理学解释。

部分数据处理脚本使用了辅助编程工具帮助形成初稿，但脚本必须经过本地运行、报错修订、输出核验和研究边界检查后才能进入项目流程。脚本不能代替研究判断。

## 三、已经形成的可复用模块

| 模块 | 已完成的内容 | 以后有什么用 | 当前不能说明什么 |
|---|---|---|---|
| 政策时间模块 | 城市政策年份、企业城市和真实处理批次G | 可用于分批实施政策研究 | 不能单独证明政策效果 |
| 分期DID模块 | 比较组、事件时间、样本支持和CS-DID技术管道 | 可快速检查新结果变量是否具备识别条件 | 没有合格结果变量时不能形成论文结论 |
| 实体映射模块 | 企业代码、CH后缀、证券和伙伴标识标准化 | 可连接企业面板、关系数据和文本 | 不能自动解决缺少国家字段的问题 |
| 关系语义模块 | 关系方向、主键、有效期和`end=4000`审计 | 防止把字段名称直接误解释为现实关系 | 不能补出数据库未提供的coverage |
| coverage审计模块 | 区分真实变化和数据库记录变化 | 可提前判断退出、进入和伙伴更替指标是否安全 | 不能把“未记录”变成“真实退出” |
| 供应商结构模块 | 已记录伙伴集合、Top1和条件HHI定义 | 可描述重点供应商结构和集中度 | 不能代表企业全部采购结构 |
| FactSet全扫模块 | 5,245,666行关系数据字段、年份和质量清点 | 为后续供应链网络研究提供底图 | 当前仍缺完整国家桥梁和coverage |
| GSDB结构模块 | 制裁事件、发起国、对象国、时间和类型 | 可用于构造国家或双边国家层冲击 | 尚不能直接形成企业层制裁暴露 |
| MD&A语料模块 | 68,470份TXT索引、编码修复和章节切分 | 可开发供应链风险、产业链安全和战略反应文本指标 | 主题和文本构念尚未完成认证 |
| 数据Atlas模块 | 数据域、字段、连接、阻断和路线死亡测试 | 新选题前先判断能否做成，减少重复试错 | 不是正式论文结果 |
| 检查点模块 | 批次、输出、异常和恢复边界记录 | 任务中断后能够从确定位置续跑 | 不能替代输出完整性验证 |

## 四、代表性脚本及作用

以下脚本名称来自V3.4A机器深度流程。脚本的职责是批量执行和生成证据，不负责决定研究结论。

### 1. `profile_all_structured_fields_v3_4a.py`

**作用**

- 扫描结构化工作簿和数据表；
- 统计每个字段的非空率、唯一值、年份范围和样例；
- 对字段是否可用于研究形成完整画像。

**怎样使用**

- 在项目配置好的Python环境中，从项目根目录运行；
- 运行前确认输入清单和输出目录；
- 运行后重点查看字段画像摘要和异常字段；
- 已完成的170字段画像不得无理由重跑。

### 2. `certify_factset_working_copy_v3_4a.py`

**作用**

- 确认当前使用的是哪一份FactSet工作副本；
- 核对文件大小、哈希和基本结构；
- 防止不同脚本误用不同版本。

**怎样使用**

- 更换FactSet工作副本或重新建立环境时运行；
- 输出应作为后续关系审计的版本凭证；
- 不用于分析政策效果。

### 3. `audit_factset_security_mapping_v3_4a.py`

**作用**

- 检查证券标识和企业实体之间的映射；
- 区分高置信、低置信和无法确认的映射；
- 为企业关系与上市公司面板连接提供依据。

**怎样使用**

- 映射表或企业样本发生变化时运行；
- 重点审核一对多、多对一和缺失候选；
- 不能把低置信候选自动当成真实企业。

### 4. `audit_factset_terminal_semantics_v3_4a.py`

**作用**

- 审计关系主键、有效期、`end=4000`和coverage状态；
- 汇总哪些字段有正式证据，哪些只能保留阻断结论。

**怎样使用**

- 关系字段解释发生变化时运行；
- 输出用于决定关系进入、退出和持续性指标的解释边界；
- 不得用脚本猜测厂商未提供的字段含义。

### 5. `audit_and_section_mda_text_v3_4a.py`

**作用**

- 检查68,470份TXT的编码和可读性；
- 将全文切分为MD&A、风险、财务附注等章节；
- 减少不同章节混在一起导致的文本噪声。

**怎样使用**

- 新增文本或修改章节规则时运行；
- 运行后检查编码异常和章节缺失清单；
- 当前全量编码和章节切分已经完成，不应在没有新输入时重跑。

### 6. `save_text_anomaly_decodes_v3_4a.py`

**作用**

- 保存编码异常文本的解码尝试和处理记录；
- 为少数异常文件提供可审计证据；
- 防止异常文件被静默丢弃。

**怎样使用**

- 对异常清单中的文件定向运行；
- 不用于重复处理全部文本；
- 输出主要供人工复核。

### 7. `build_fulltext_representations_v3_4a.py`

**作用**

- 将全文转换为七类机器可读文本表示；
- 按批次生成稀疏矩阵；
- 为主题模型、相似度分析和残余文本识别提供输入。

**怎样使用**

- 必须遵循检查点和断点续跑规则；
- 当前第1—76批已存在，第77—92批缺失；
- 在定向NPZ加载抽检通过前，不得直接续跑；
- 续跑时必须确认脚本会跳过已完成批次，不覆盖第1—76批。

### 8. `run_topic_ensemble_v3_4a.py`

**作用**

- 使用多种主题方法识别文本中的稳定内容结构；
- 比较不同方法和参数下主题是否一致；
- 避免把单一模型偶然生成的主题当成研究构念。

**怎样使用**

- 只能在全部七类全文表示92/92完成并验证后运行；
- 输出包括主题、关键词、文档分配和稳定性结果；
- 当前尚未执行。

### 9. `rebuild_semantic_residuals_v3_4a.py`

**作用**

- 找出没有被现有主题充分解释的文本；
- 生成需要进一步人工阅读的语义残余队列；
- 帮助发现稀有主题、异常企业或遗漏构念。

**怎样使用**

- 只能在主题模型完成并验证后运行；
- 残余队列用于后续语义阅读，不是自动生成论文结论；
- 当前尚未执行。

### 10. `finalize_machine_deep_atlas_v3_4a.py`

**作用**

- 汇总字段、关系、文本表示、主题和残余结果；
- 生成机器深度Atlas主报告、检查点和交接包；
- 判断机器阶段是否达到完成条件。

**怎样使用**

- 只能在所有前置任务完成并验证后运行；
- 任何前置项未完成时都不得生成“机器深度完成”结论；
- 当前尚未执行。

## 五、这些成果怎样支持下一篇论文

当前最重要的价值不是得到某个显著系数，而是已经建立了一个可复用的研究基础：

1. 新政策题目可以快速检查政策时间、真实G和样本支持；
2. 新关系题目可以先判断coverage和实体映射是否允许正式解释；
3. 新文本题目可以直接使用经过编码和章节处理的MD&A语料；
4. 地缘政治方向可以在国家—企业桥梁获得认证后接入GSDB；
5. 新路线可以在正式估计前接受字段、映射、coverage和识别死亡测试。

这能够减少“模型跑到后面才发现数据不能支持论文”的重复损失。
