# 研究题目演变与终止原因（通俗版）

更新时间：2026-07-23

## 一、为什么需要先做题目筛选，而不是直接跑模型

本项目面对的不是一张已经整理好的标准数据表，而是政策、企业、供应链关系、制裁事件和上市公司文本等多类数据。每类数据的观察单位、时间口径、企业标识和覆盖范围都不同。

因此，前期工作的重点不是尽快得到一个显著结果，而是依次回答四个问题：

1. 研究问题是否重要；
2. 处理变量和结果变量能否被准确界定；
3. 不同数据能否可靠连接；
4. 样本是否足以支撑正式识别和论文贡献。

前期曾形成一个地缘政治候选方向，并先后实质推进了两个链长制题目。后两个题目均在正式论文主规格和正式结果解释之前停止。

---

## 二、早期候选方向：制裁或地缘政治冲击与企业供应链反应

### 1. 当时考虑的题目

候选题目大致为：

> 制裁或地缘政治冲击如何影响中国企业的供应链关系持续性、网络重构和战略反应。

也考虑过把研究对象进一步聚焦到新能源企业、供应链安全、进口替代或企业风险披露。

### 2. 为什么考虑这个方向

这个方向有三个吸引力：

- **现实意义较强**：制裁、出口管制和地缘政治摩擦会直接影响企业采购、客户和技术来源；
- **研究空间较大**：相比一般的财务结果，更有机会讨论供应链网络和企业战略反应；
- **现有数据看似可以互补**：
  - GSDB提供国家或双边国家层面的制裁事件；
  - FactSet/Revere提供上市公司供应商—客户关系；
  - MD&A文本可能反映企业对供应链风险、进口替代和产业链安全的讨论。

### 3. 已经做过的准备

- 清点GSDB制裁事件的国家、时间和类型结构；
- 全量扫描FactSet/Revere关系数据及主要字段；
- 检查企业、证券和伙伴标识的映射可能性；
- 审计关系有效期、关系主键、`end=4000`和数据库coverage；
- 建立MD&A全文机器索引、编码审计和章节切分；
- 开始构造全文表示，为以后识别稳定文本主题做准备。

### 4. 当前为什么没有直接进入正式研究

这个方向**不是正式终止**，而是暂时保留为待认证候选。当前主要障碍是：

- GSDB主要是国家或国家对层面的事件，不能天然落到企业；
- FactSet当前材料缺少完整的企业或伙伴国家桥梁；
- coverage不足时，数据库中没有出现某条关系，不等于现实关系已经结束；
- 关系主键和部分有效期字段仍有解释边界；
- MD&A文本虽然已经完成机器索引，但稳定文本构念尚未完成认证。

通俗地说，事件日历、企业关系表和企业报告都已经找到，但把三张地图准确叠在一起的“坐标转换”还没有完全解决。

## 三、停止题目一：链长制政策与企业供应链韧性

### 1. 原拟题目

> 链长制政策能否提升上市公司的供应链韧性，以及这种影响通过什么机制实现。

### 2. 为什么最初优先推进

当时认为这一题目相对容易形成完整研究：

- 有城市链长制政策实施时间；
- 有企业与城市的连接信息；
- 可以形成企业—年份面板；
- 政策分批实施，适合使用现代分期DID方法；
- 本地材料中存在一个名为“供应链韧性”的成品指标，看起来可以直接作为结果变量。

### 3. 已开展的工作和实验

#### 政策与样本部分

- 核对城市政策实施年份；
- 检查企业注册地址和城市归属；
- 构造企业真正开始受政策影响的年份，即真实处理批次G；
- 区分尚未处理企业和从不处理企业；
- 检查事件时间、处理前后样本和城市聚类支持；
- 建立现代分期DID和CS-DID技术验证管道；
- 对真实G、包内处理行为和固定种子重复性进行核验。

#### 结果变量部分

- 追查成品供应链韧性指数的来源、公式、方向和底层字段；
- 尝试从年度财务、季度信息、专利、行业以及母子公司数据重构五维韧性指标；
- 检查本地数据库能否提供严格复现所需的全部输入。

### 4. 为什么做不下去

核心问题不在于结果是否显著，而在于结果变量不能被严格证明：

- 成品韧性指数缺少足够正式的来源、公式和口径证据；
- 严格五维重构需要的财务、季度、专利和母子公司映射不完整；
- 部分字段名称存在，但不能确认其与论文指标定义完全一致；
- 在结果变量本身没有通过审计前，即使模型可以运行，也不能形成可靠论文结论。

通俗地说，政策时间和实验框架已经搭好，但最重要的“测量仪器”没有校准。此时继续估计，只会得到一个看似精确但含义不确定的数字。

### 5. 终止边界

该题目已经开展探索性和技术验证估计，但在进入正式论文主规格、正式结果解释和论文写作之前终止。

这不表示：

- 链长制政策没有效果；
- 供应链韧性理论不成立；
- 某个探索性结果不显著；
- 已经得到可以写入论文的政策结论。

## 四、停止题目二：链长制政策与供应链关系重构或供应商集中度

### 1. 原拟题目

在韧性指数受阻后，题目调整为：

> 链长制政策是否促进企业供应商或客户关系稳定、伙伴更替、关系重构和供应商结构优化。

进一步尝试的结果包括：

- 已记录供应商或客户集合变化；
- 供应商更替；
- 最大供应商成本占比Top1；
- 已记录供应商集合内部的条件HHI集中度。

### 2. 为什么改做这个题目

这个调整的逻辑是：

- 不再依赖来源不明的成品韧性指数；
- 尝试直接从供应商—客户关系数据构造更透明的结果；
- 供应链关系和供应商集中度与链长制的政策目标具有较直观联系；
- 部分成本占比字段可以直接用于构造Top1和条件HHI。

### 3. 已开展的工作和实验

- 修正企业代码格式和CH市场后缀；
- 统一焦点企业、供应商和客户标识；
- 检查关系方向、连续记录和伙伴ID；
- 审计数据库coverage及其选择问题；
- 构造已记录供应商和客户集合变化；
- 检查供应商更替和关系持续性；
- 核验供应商成本占比定义；
- 构造Top1和条件HHI；
- 对候选政策单元执行处理前后样本、城市支持和比较组审计；
- 检查客户方向可能存在的coverage选择风险。

### 4. 为什么做不下去

#### 第一类问题：数据库没有记录，不等于现实关系退出

FactSet/Revere更接近重点关系记录库，而不是企业全部供应链关系的完整普查。没有coverage时：

- 一条关系从数据库中消失，可能是真实退出；
- 也可能是数据库覆盖变化；
- 还可能是披露口径变化。

因此，结果只能谨慎称为“已记录主要伙伴集合变化”，不能直接称为真实供应商退出或客户流失。

#### 第二类问题：客户方向选择风险更高

客户披露和重点客户覆盖可能受企业规模、披露规则和数据库收录逻辑影响，正式解释风险较高。

#### 第三类问题：政策单元支持不足

在六个候选政策单元中，只有一个达到最低双侧城市支持。有效结构接近一个早期处理批次和一个主要后期，难以支撑完整、有说服力的政策论文。

#### 第四类问题：可计算不等于可形成论文

Top1和条件HHI可以计算，但：

- 它们只是在已记录供应商集合内部的结构指标；
- 不是企业全部采购结构；
- 政策单元和比较组支持又不足；
- 即使继续运行，也很难形成足够完整的识别和论文贡献。

### 5. 终止边界

该题目同样已经开展探索性和技术验证估计，但在进入正式论文主规格、正式结果解释和论文写作之前终止。

路线B整体状态保持：

`TERMINATED_DO_NOT_REVIVE`

除非未来取得新的正式结果变量、coverage证据和更充分政策支持，否则不应因为旧探索性结果而恢复。

## 五、两个停止题目留下了什么

停止题目不等于此前工作没有价值。两个题目共同留下了：

- 政策时间和真实处理批次审计；
- 企业—城市匹配；
- 现代分期DID技术管道；
- 企业和证券代码标准化；
- 关系方向、主键和有效期审计；
- coverage边界识别；
- 供应商集合、Top1和条件HHI的透明定义；
- 政策单元支持审计；
- 一套“正式估计前先做数据死亡测试”的流程。

这些模块能够直接用于今后的政策研究、供应链关系研究和新选题可行性判断。
