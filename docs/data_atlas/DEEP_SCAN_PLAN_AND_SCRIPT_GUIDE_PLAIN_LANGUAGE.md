# 数据深度扫描计划与脚本说明（通俗版）

更新时间：2026-07-23

## 一、深度扫描的目标

深度扫描不是简单地“把所有文件读一遍”，而是要建立一套能够回答以下问题的机器证据链：

- 数据到底有哪些；
- 每个字段代表什么；
- 不同数据能否连接；
- 文本中稳定存在什么主题；
- 哪些内容无法被现有主题解释；
- 哪些研究路线有足够的数据支持；
- 哪些路线应在正式估计前停止。

脚本承担批量扫描、统计、索引和检查点工作。研究者负责规则制定、异常审核、主题解释和研究决策。自动化处理不能替代对变量含义和因果识别的判断。

## 三、后续工作分为六个阶段

## 阶段0：环境和已有矩阵完整性验证

### 目标

在继续生成第77批之前，确认第1—76批可以被原有科学计算环境正常读取。

### 具体工作

1. 找到生成矩阵时使用的Python和SciPy环境；
2. 对每类表示的第1批和第76批执行只读`load_npz`抽检；
3. 额外检查`risk_char_2_3gram_tfidf`第1、2批；
4. 记录shape、nnz、dtype和读取错误；
5. 确认表示脚本具有跳过已完成批次的逻辑；
6. 确认不会覆盖第1—76批。

### 通过标准

全部目标文件能只读加载，并且脚本能够从首个缺失批次继续。

通过后状态才可以改为：

`SAFE_TO_RESUME_FROM_BATCH_77`

## 阶段2：运行主题模型集成

### 使用脚本

`run_topic_ensemble_v3_4a.py`

### 目标

不是只得到一套主题，而是比较多种方法和参数，寻找稳定出现的主题结构。

### 主要输出

- 各方法主题关键词；
- 文档—主题分配；
- 主题相似度；
- 跨方法稳定性；
- 稳定主题候选；
- 不稳定主题和异常主题清单。

### 人工审核重点

- 主题是否有清晰管理学或供应链含义；
- 是否只是年份、格式或公司名称造成的伪主题；
- 供应链风险、客户、采购、库存、物流、制裁、进口替代等内容是否能够区分；
- 主题在不同年份和企业中是否稳定。

### 通过标准

至少形成可解释、跨方法相对稳定且能够回到原文核验的主题候选。

---

## 阶段3：重建语义残余队列

### 使用脚本

`rebuild_semantic_residuals_v3_4a.py`

### 目标

找出主题模型没有充分解释的文本，建立下一步人工语义阅读清单。

### 主要输出

- 高残余文本；
- 稀有主题候选；
- 异常企业或异常年份；
- 可能遗漏的新构念；
- 优先人工阅读队列。

### 人工审核重点

- 残余是编码噪声、格式问题，还是新主题；
- 是否存在少数但有研究价值的地缘政治或供应链事件；
- 是否存在主题模型将不同机制错误合并的情况。

### 通过标准

残余能够被分为已知噪声、已有主题扩展、新候选主题和无法判断四类，并形成可执行阅读队列。

---

## 阶段4：留出检验和语义饱和

这一阶段不应只依赖脚本自动判断。

### 目标

验证新读取的文本是否还会不断产生新主题。

### 做法

- 预先保留一批未参与主题开发的文本；
- 分批进行语义阅读；
- 记录每批是否出现新主题、新机制或新数据问题；
- 连续多批不再出现有价值的新主题后，才判断接近语义饱和。

### 通过标准

留出样本没有推翻现有主题结构，连续阅读批次不再产生实质性新构念。

---

## 阶段5：运行finalizer

### 使用脚本

`finalize_machine_deep_atlas_v3_4a.py`

### 目标

汇总全部机器扫描、表示、主题、残余和审计结果，形成统一的Atlas状态。

### 最终输出应包括

- 数据域和文件范围；
- 结构化字段状态；
- FactSet关系语义状态；
- 文本表示完成状态；
- 稳定主题候选；
- 语义残余和阅读队列；
- 未解决阻断；
- 可行研究路线；
- 不可行研究路线；
- 检查点；
- 交接包；
- 当前能声称和不能声称的内容。

### 通过标准

所有前置项完成并验证，且报告中不把机器输出直接写成正式论文结论。

## 阶段6：正式选题前的数据死亡测试

机器深度Atlas完成后，每条候选路线都要经过以下检查：

1. **处理是否清楚**：冲击、政策或事件能否准确落到企业和年份；
2. **结果是否真实**：变量有正式定义，且不是数据库coverage造成的假变化；
3. **映射是否可靠**：企业、证券、伙伴、城市和国家能够连接；
4. **识别是否支持**：有足够处理单元、比较组、处理前后期和聚类；
5. **机制是否可验证**：机制变量不是临时拼接；
6. **贡献是否足够**：不是只有一个批次或一个局部结果；
7. **解释边界是否清楚**：能够明确说出数据库看得到和看不到什么。

只有通过死亡测试的路线，才进入正式论文估计。

## 四、最终完成后能够达到什么程度

所有机器和语义阶段完成后，项目应达到以下状态：

### 1. 数据层面

- 每个数据域有范围、年份、观察单位和版本记录；
- 每个重要字段有完整度、定义证据和可用状态；
- 每条关键连接有映射质量和失败原因；
- 大型数据不上传，但有哈希、清单和复现路径。

### 2. 文本层面

- 68,470份文本都有编码和章节状态；
- 七类全文表示完整；
- 主题结构经过多方法稳定性检查；
- 残余文本有清晰队列；
- 留出和语义饱和有记录；
- 可以提出经过认证的文本构念候选。

### 3. 选题层面

- 能明确列出A、B、C级候选路线；
- 每条路线都有处理、结果、映射、识别和阻断证据；
- 能在正式估计前排除明显不可行路线；
- 能解释为什么某条路线值得继续，而不是只因为模型能运行。

### 4. 复现和交接层面

- 每个任务有脚本、检查点、输出和运行记录；
- 中断后可以从明确批次恢复；
- 不依赖某一段聊天记录才能理解项目；
- 新研究人员可以通过Atlas和交接包了解当前状态。

### 5. 不能自动达到的内容

即使深度扫描完成，也不等于：

- 已经确定最终论文题目；
- 已经证明某项政策有效；
- 已经形成可发表结论；
- 机器主题可以直接替代理论构念；
- 所有文本都已经人工逐篇阅读。

深度扫描的最终价值，是为选题、理论、识别和正式估计提供一份可靠的数据底图。
